## 1. Package thesis

The C-Governed CLI Agent Mesh package is an executable-worker governance layer over the existing `c = a + b` corpus.

It specializes existing SER / L4 / witness / memory-gate / review concepts for the operational fact that `c` may govern multiple executable CLI/cloud agents.

The central claim:

> A persistent `c` may use many executable agents, but no executable agent may silently become `c` authority.

The central design rule:

> CLI agents are workers. They may act only under registry eligibility, task contract, scoped permission, sandbox/worktree boundary, witness, review, and memory/release gate. They may not self-authorize, self-approve, write core memory, mutate identity, leak secrets, bypass human gates, or retaliate against external systems.

---

## 2. Corpus bridge set

### 2.1 Explicit bridge: `c = a + b`

CLI agents belong to `b`, the technological substrate. They may provide hands, eyes, tests, reports, diffs, and controlled execution. They are not the human anchor `a` and do not become the persistent entity `c`.

### 2.2 Quiet bridge I: information theory

The package reduces ambiguity by turning agent authority into named objects: task contracts, permission grants, registry entries, witness events, raw evidence sidecars, memory gate records, release surface records, checker runs, and conformance results.

### 2.3 Quiet bridge II: cybernetics

A worker mesh is a control system. The controller must not be confused with the actuators. The package defines negative feedback: hold, deny, freeze, quarantine, revoke, rollback, review, and red-line failure.

### 2.4 Earth paragraph

This index is the table of contents taped to the inside of the electrical cabinet. Without it, a worker opens the door and sees only wires. With it, the worker knows which breaker controls the oven, which controls the bathroom, and which must not be touched without the owner standing there.
